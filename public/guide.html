MCP setup & usage

Choose what your project can access, connect your assistant, then ask it to use a saved workflow.

1. Choose skills for a project

To add skills already installed on this computer, use Scan installed skills in the library header. Scan global folders, registered projects, or both; add workspace/custom folders for other locations. Review the source and coverage report, then import. New imports remain disabled, and original platform installations are unchanged. The scan does not verify cloud accounts or what an agent currently loads. After scanning, Found on this computer groups observed skills by global installations and discovered project directories, including packages not yet imported. Expand a skill’s source locations for its platform, path and last-seen time. These source groups are separate from Project access; finding a skill does not enable it.

Open the library and select a project, or create one with the plus button. Each project has its own saved selection.

  • Collections group related skills. A collection checkbox enables or disables every member; expand it to choose individual skills. A minus means only some are enabled.
  • Standalone skills have their own switch. Enabling one makes its instructions and included workflows available.

Disabled skills stay in your library and are hidden from that project’s MCP tools. New imports start disabled. A collection checkbox affects all members, including ones hidden by the current search or filter.

Choose project skills

2. Connect your assistant

Add the library server to your assistant’s MCP settings. The examples below use placeholders only and do not read your saved projects or local paths. Replace the paths and project ID before connecting. For ready-to-use settings, select a project in the library and choose Connect project.

Replace all placeholder paths and the project ID with your own values.

[mcp_servers.skills]
command = "node"
args = ["/absolute/path/to/library-server/dist/stdio.js"]

[mcp_servers.skills.env]
SKILL_LIBRARY_PROJECT = "your-project-id"
SKILL_LIBRARY_DIR = "/absolute/path/to/library"
  1. Choose the format your MCP client supports. Replace your-project-id with the profile ID from the library and each /absolute/path/to/… value with its actual location. Merge the result into the client’s existing MCP settings.
  2. Reconnect the MCP server in your assistant, or restart the client if it requires that.
  3. Ask: List the skills available from the connected library. The result should match this project’s enabled selection.

Use stdio for a local process: your assistant starts Node itself, so the browser server can be closed. Use HTTP for the running local server: keep npm run ui running. The loopback URL is only reachable on this computer; a hosted assistant cannot reach it directly.

Keep the project ID in the configuration. A connection without SKILL_LIBRARY_PROJECT or the HTTP ?project=… query has access to the full library.

Client setup reference: Official Codex MCP documentation. JSON settings depend on your MCP client’s configuration format.

3. Ask your assistant to use a workflow

Enable the relevant skill, then give your assistant a concrete task. You can name the library explicitly:

Search the connected library for a debugging workflow. Read the matching skill, check its requirements, and use it to investigate this error: [paste the error].

For another type of task, describe the outcome and let the assistant find a relevant skill:

Find an available workflow for [task]. Read its instructions, check any setup requirements, and apply it to [relevant file or page].

The assistant searches metadata, retrieves the selected skill’s instructions, and reads supporting files as needed. It then does the work with its own browser, filesystem and shell tools.

Enabling means available to retrieve. It does not force the assistant to use a skill, install an extension, or execute code. Some skills require additional tools, credentials, or helper programs. Review each skill’s requirements and follow its documented setup or fallback instructions.

The four MCP tools

Every tool respects the connected project’s selection. They retrieve content and do not change the library.

ToolWhen it runsMain inputs
search_skillsFind workflows for a task; returns metadata and requirements.query; optional tags, capabilities, limit
list_skillsBrowse available metadata. Follow next_cursor for more pages.Optional tags, preferred_only, limit, cursor
get_skillLoad instructions and the supporting-file manifest.skill_id; optional revision
read_skill_fileRead a referenced file from that exact skill snapshot.skill_id, returned revision, manifest path

The assistant should reuse the revision from get_skill when reading supporting files. Skills can require capabilities your assistant does not have; the library’s requirement labels do not verify its runtime.

What runs where

  1. You → browser UI. Select skills; the local owner API saves IDs in library/projects.json.
  2. Assistant → MCP server. Your client calls one of the four retrieval tools over stdio or HTTP.
  3. Server → local files. The server filters by project and reads the saved package snapshot. It does not call an AI provider or GitHub during retrieval.
  4. Assistant → its own tools. The assistant follows the retrieved workflow. Its model usage, tool access, and any external calls depend on that assistant and the task.

GitHub links show provenance; clicking one opens the upstream source. Changing a project selection applies on its next tool call. Instructions already loaded into an assistant’s conversation are not erased. New imports appear immediately through the running website and HTTP server. Reconnect existing stdio library processes to load a fresh package snapshot.

Marketplace setup

The Marketplace uses a separate read-only discovery MCP on this computer. Keep both services running. No deployment is needed.

# In the discovery server repository (Node 22 or newer)
npm install
npx vercel login
npx vercel link
npx vercel env pull .env.local
npm run build
npm run http

# In the library server repository, in another terminal
npm run ui

Choose your own Vercel team and the project you intend to use for API authentication when linking. No particular team or project name is required. The ignored .env.local contains an OIDC token; keep it private. Refresh with npm run auth:refresh and restart the discovery service if authentication expires. The discovery service starts at http://127.0.0.1:3334/mcp. Set SKILL_MARKETPLACE_URL on the library server only if you change that local endpoint.

All rankings and search show project collections. Open a collection for its project description and individual skill summaries. Most installed, Trending, and Hot now group the first 500 provider-ranked skills, ordered by each project’s highest-ranked member. Most installed uses all-time skill installs; Trending preserves the provider’s trending order; Hot now uses hourly installs compared with the same hour yesterday. Search groups up to 50 matching skills in first-match order. Counts describe distinct skills in the sampled window, not total project downloads or the full repository. GitHub stars ranks public repositories with the agent-skills topic, then checks for valid skills before allowing installation. Rankings and search cache for one minute; repository metadata for five minutes and immutable verified files for up to 24 hours. Each result shows its provider retrieval time.

GitHub’s unauthenticated rate limit may interrupt large collections. Optionally set GITHUB_TOKEN in the discovery service’s private .env.local. No private repository access is supported. See skills.sh API authentication and GitHub repository search.

Connect another agent to discovery

Use the running Streamable HTTP endpoint http://127.0.0.1:3334/mcp, or launch the discovery repository with npm start as a stdio server. Set the client’s working directory to that repository so its ignored environment file can be loaded. Discovery tools are search_marketplace, list_rankings, list_repository_skills and get_marketplace_skill. They inspect sources and return manifests; installation is available only through this local app.

Install and activate coding-app copies

  1. Choose a skill in Marketplace. GitHub repositories first open a picker of verified skills. Inspect the instructions, source commit, and repository setup.
  2. Choose Install, then optionally select a project, its existing absolute directory, and Codex, Claude Code or Cursor destinations.
  3. Install saves the skill disabled. Install & enable for this project also activates it. Existing installations keep their current selection when simply configured again.
  4. Use the project’s skill or collection switch to activate or deactivate later. Enabled native bindings copy to .agents/skills for Codex, .claude/skills for Claude Code and .cursor/skills for Cursor. Existing library skills also offer Install in coding apps in their details.

Copied packages include attribution and an ownership marker. The app only removes unchanged copies it manages. Conflicting names, edited files or symlinked destination folders stop activation with a conflict; move or resolve that installation yourself and retry. Destination changes are staged together and rolled back before a failed activation is committed. A saved library package can remain after native activation fails; the dialog reports that explicitly.

Restarting the local server recovers interrupted native operations from its journal. If recovery reports an occupied destination or changed project settings, preserve library/native-transaction.json and its staging folders and resolve the reported conflict before retrying. Do not delete recovery files to force activation.

Reload or restart your coding agent if its skill list has not refreshed. A project switch blocks future MCP reads and updates managed files, but cannot withdraw instructions already loaded into a conversation. Existing projects stay MCP-only until you configure native destinations. Installation copies files and never runs repository setup scripts; follow additional setup instructions separately after reviewing them.

Native skill references: Codex, Claude Code, Cursor.

Troubleshooting

No skills appear

Check that the intended project has at least one skill enabled and that your MCP configuration points to the same project ID. A new project is empty by default.

A disabled skill still seems available

Check for an unscoped connection or another installation of the skill. The library blocks new project-scoped reads, but cannot remove instructions already loaded into the assistant’s conversation.

The connection fails

For stdio, verify that Node is available and all placeholder paths have been replaced and run npm run build in the repository. For HTTP, start npm run ui and keep it running. Update the paths after moving the repository, or copy fresh settings from Connect project in the library.

A supporting file or revision is missing

Reconnect after importing or changing packages. Ask the assistant to retrieve the skill again, then read a path and revision from its new manifest.

How do I add another skill?

Open Marketplace to inspect and install a public GitHub skill, or use the local import command in the repository. Pass --folder "Collection name" to choose a collection. Use --standalone for a standalone skill, then restart the server. Project selections are explicit; new imports are not automatically enabled.
